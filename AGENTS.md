# Контекст проекта ЯГТУ

## Назначение

Это статический frontend сайта ЯГТУ. В дальнейшем шаблоны будут интегрированы в 1С-Битрикс, поэтому контент, карточки и фильтры должны оставаться пригодными для динамического вывода.

Основной язык общения и комментариев — русский.

## Макеты

Figma-файл «Ассеты»:

https://www.figma.com/design/qyrja1BsjYTMNKVhQZj5Dt/Ассеты

Перед реализацией конкретного экрана сверять его с переданным пользователем `node-id`. Не считать ранее использованный фрейм актуальным, если пользователь прислал новую ссылку.

## Структура проекта

- HTML-страницы находятся в `pages/`.
- Общая точка подключения стилей — `css/styles.css`.
- Стили компонентов находятся в `css/components/`.
- Основная инициализация JavaScript — `js/main.js`.
- JS отдельных компонентов находится в `js/components/`.
- Изображения-заглушки находятся в `images/fallback/`.
- SVG находятся в `images/svg/`.

Главная страница проекта — `pages/index.html`, а не файл в корне.

## Правила работы

- Сохранять существующий стиль разметки и именование классов по БЭМ.
- Не переписывать пользовательские изменения и перед правкой проверять актуальное содержимое файла.
- Переиспользовать существующие шапку, футер и общие компоненты со страниц проекта.
- Не создавать дублирующие стили, если подходящий компонент уже существует.
- Для простых flex-компоновок по возможности использовать утилиты Bootstrap (`d-flex` и связанные классы), но не проводить массовую замену без отдельного согласования.
- Не добавлять CSS или JS, если пользователь просит только HTML-структуру.
- Не подключать внешние API без прямого подтверждения пользователя.
- Для интерактивных элементов учитывать клавиатуру, `aria-*` и `prefers-reduced-motion`.
- После изменений проверять `git diff --check`; после изменений JS также запускать `node --check` для затронутых файлов.
- Не коммитить и не отправлять изменения без отдельной просьбы.

## Текущие решения

### Каталоги и фильтры

- `pages/vacancies.html` и `pages/programs.html` унифицированы по общей логике листинга.
- Карточки программ используют разные модифицирующие классы.
- Панели фильтров раскрываются как единый аккордеон под кнопкой «Фильтр».
- На десктопе раскрытие фильтров не должно сдвигать всю страницу.

### Карта

- Страница карты — `pages/map.html`.
- Сейчас используется статическая карта; подключение API Яндекс Карт отложено.
- Пины имеют подписи и popup при наведении/фокусе.
- Popup не должен обрезаться родительским `overflow`.
- Фильтры объектов и подразделений реализуются как аккордеоны.

### Детальная страница подразделения

- Страница — `pages/detail-structure.html`.
- Стили — `css/components/detail-structure.css`.
- Галерея `.structure-gallery__list` работает через Swiper.
- В галерее предусмотрены 4 элемента, стрелки и пагинация по образцу слайдеров главной страницы.
- Инициализация галереи находится в `js/main.js` по классу `.js-init-structure-gallery`.

### Студенческая жизнь

- Страница — `pages/student-life.html`.
- В слайдерах присутствуют маленькая и большая пары стрелок.
- Если большая пара сохраняется, её состояние необходимо синхронизировать со Swiper: повторять `swiper-button-disabled`, `aria-disabled` и `tabindex` на событиях `init`, `slideChange`, `lock` и `unlock`.

### Шапка

- Бургер плавно превращается в крестик.
- В открытом состоянии надпись «Меню» скрывается через `display: none`, а кнопка становится круглой.
- Следить, чтобы в закрытом состоянии слово «МЕНЮ» не обрезалось.

### Флагманские проекты

- Стили находятся в `css/components/flagship-projects.css`.
- Декоративные линии карточек в `::after` плавно увеличиваются при наведении.
- Анимация должна учитывать `prefers-reduced-motion`.

## Важное замечание

Этот файл хранит устойчивый контекст проекта, но не заменяет актуальную задачу пользователя. Последняя просьба пользователя всегда имеет приоритет над описанными здесь решениями.
