# Повторное использование компонентов

## Инициализация вставленного блока

После вставки готовой разметки в DOM вызвать `await window.SiteUI.init(container)`. Метод ждёт загрузки библиотек и инициализирует табы, пагинацию, аккордеоны, фильтры, поиск, модалки, проверку полей и галереи внутри переданного контейнера. Повторный вызов не добавляет дублирующиеся обработчики. Для одной галереи можно использовать `await window.Galleries.init(element)`. Готовность первоначальной страницы — `await window.SiteUI.ready`.

Эти API предназначены для добавления целых экземпляров. Поиск каталога заново читает карточки при выполнении поиска, пагинация обновляет набор при повторном init. Для изменения структуры уже инициализированного набора табов/полей лучше вставлять новый экземпляр; общего destroy API пока нет. Подключать main.js достаточно один раз.

## Независимые экземпляры

- Выдачи: задать стабильный уникальный `data-pagination-key="secondary"` контейнеру экземпляра. Он использует `secondary-page` и `secondary-tab` в URL. Первый неназванный листинг сохраняет прежние `page/tab`, последующие получают автоматические имена `listing-N`. Для сохранения ссылок при перестановке блоков нужен явный ключ. `data-pagination-url="off"` отключает синхронизацию с URL.
- Модалки: `data-modal-target="dialog-id"` или `aria-controls="dialog-id"` явно указывают окно. Старый `data-modal` сохраняется. Обёртка `data-ui="modal-scope"` локализует поиск одноимённых окон. При повторном включении event-modal.njk передавать уникальные `eventModalId`, `eventModalKey` и `modalIdPrefix`, чтобы ID, label/for и aria-labelledby не дублировались.
- Панели фильтров: ID панели и соответствующий data-open-filter-panel должны быть уникальны; поиск кнопок выполняется в ближайшем listing-page, а не во всех каталогах сразу.
- Сетка Полезных ссылок определена в её собственном CSS и адаптируется к ширине компонента. Порядковое назначение декора сохранено намеренно.
- Направления адаптируются к контейнеру, а не только окну. Слайды и управление каждого экземпляра локальны.
- Описание экзаменов оформляется в собственном program-exams.css; вариант чёрной плашки института задаётся structure__program--plain без зависимости от university-statistics.

Объединение дублирующихся шаблонов направлений и карточек программ отложено до отдельного согласования. Существующие шаблоны и БЭМ-имена сохранены.

Компоненты подключаются общей точкой styles/styles.css и js/main.js, а не названием страницы. Существующие БЭМ-имена сохранены для совместимости; префикс student/program не требует родительского элемента страницы.

- Карточки ссылок: components/student-links.njk, стили src/styles/components/student-links.css. Каждая ссылка занимает всю карточку. Hover определяется возможностями указателя, не шириной окна.
- Направления: .student-directions и .student-direction, общий components/student-gallery.njk, стили src/styles/components/student-directions.css. Каждый js-init-student-slider инициализируется отдельно, со своими стрелками и пагинацией.
- Показатели и раскрывающийся контент: components/program-exams.njk, стили src/styles/components/program-exams.css. Анимация details включается атрибутом data-ui="disclosure", использует семантический summary, поддерживает несколько экземпляров и reduced-motion.
- Классический аккордеон использует data-ui="dropdown--item", dropdown--header, dropdown--trigger, dropdown--content. Не переименовывать эти атрибуты при изменении оформления.
- Для динамически вставленного блока вызвать window.Dropdown.init(container). Повторная инициализация безопасна: обработчики не дублируются. Это общая точка входа обоих вариантов аккордеона.
- Фильтры программ: отдельная группа data-ui="structure-detail__tabs" в контейнере data-ui="structure-detail__section"; карточки data-ui="training-program-card" и data-category. Для произвольных динамических названий передавать data-filter кнопки и data-category карточки с одинаковыми ключами. Группы не используют глобальные ID.

UI Kit использует те же шаблоны галерей и общую логику, что рабочие страницы. Отдельный пример тематических кнопок демонстрирует их состояния; полноценная выдача и переключение Новостей/Событий находятся в полном блоке выше. Декоративные SVG не являются UI-спрайтом.
