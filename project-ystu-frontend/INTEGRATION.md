# Интеграция шаблонов ЯГТУ в 1С-Битрикс

## Что передаётся

`src` — редактируемые исходники; `dist` — готовая статическая сборка. Nunjucks используется только на компьютере разработчика при сборке. На сервере сайта он не нужен. Исходная вёрстка и поведение компонентов сохранены; эта реорганизация не добавляет серверную обработку.

## Общие компоненты

- `src/templates/components/header.njk` — единственный шаблон основной шапки и мега-меню.
- `navbar.njk` — верхняя навигация, иконки и телефон.
- `footer.njk` — единственный шаблон подвала.
- `cookie-banner.njk` — уведомление о cookie.
- `event-modal.njk`, `vacancy-modal.njk` — формы и состояния успешной отправки.
- `preparatory-courses.njk` — общий баннер с параметрами из `src/data/pages.json`.
- `src/data/navigation.json` — пункты первого уровня мега-меню. Ссылки остальных уровней находятся в `header.njk`.
- `src/data/components.json` — автоматически обновляемый индекс шаблонов и мест использования.

UI-kit подключает общие шаблоны через include. Его пояснения, демонстрационные обёртки и уникальные варианты остаются в `src/pages/ui-kit.njk`. Например, показ ошибки формы — вариант общего шаблона, а не отдельная копия формы.

Сохранены существующие различия: переносы в навигации страницы сотрудника (`headerRowBreaks`), префиксы ID в UI-kit (`headerIdPrefix`, `modalIdPrefix`, `modalSuccessId`), демонстрация ошибки (`modalDemoError`) и ссылки согласия (`modalConsentLink`). Эти параметры не меняют остальные страницы.

## Порядок интеграции

1. Выполнить `npm ci`, `npm test` и открыть `dist/pages/ui-kit.html` через локальный сервер.
2. Использовать HTML из `dist/pages/` как образцы результата. Перенести общие части в шаблон сайта и компоненты Битрикс. Прямое выполнение `.njk` в PHP не предполагается.
3. Сохранить БЭМ-классы, `data-*`, структуру слайдеров, соответствие ID и `aria-*`. JavaScript использует их для инициализации и связи элементов.
4. Подключить `styles/styles.css` и `js/main.js`; сохранить относительные пути ресурсов либо централизованно адаптировать их к пути шаблона Битрикс. Не подключать библиотеки повторно.
5. Заменить демонстрационные тексты и ссылки, карточки и пункты меню динамическим выводом.
6. Подключить серверную обработку форм: проверку данных, защиту от подделки запросов, ограничения загрузки файлов, отправку и обработку ошибок. Сейчас `data-modal-demo` означает демонстрационный сценарий, а не подтверждение серверной отправки. Успешное окно показывать после успешного ответа сервера.
7. Подключить реальные поиск, фильтрацию и пагинацию. Проверить повторную инициализацию интерактивных компонентов после AJAX-обновлений: текущий проект не гарантирует её для произвольной вставки HTML.
8. Для карты проверить ключ и разрешённые домены, заменить предварительные координаты объектов подтверждёнными. При недоступности API предусмотрена статическая подложка. `map-test.html` — диагностическая страница, не раздел сайта.
9. Проверить результат на мобильных, планшетных и десктопных ширинах, доступность с клавиатуры, реальные данные, ошибки отправки и длинные заголовки.

## Границы передачи

Бэкенд, административная часть, настоящая отправка форм, данные CMS и настройки рабочего сервера в эту статическую сборку не входят. Она не является повторным аудитом дизайна или гарантией отсутствия ранее существовавших замечаний доступности. Демонстрационные `alt="Тест"` заменены описаниями, у декоративных иконок используется пустой alt, а назначение иконок-ссылок задано на ссылках. При замене изображений через CMS необходимо обновлять и альтернативные тексты. Оставшиеся ссылки `#` нужно заменить рабочими адресами.

## Исправления от 07.10.2026

- Поиск каталога выполняется по текстам карточек, уже присутствующих на странице. Серверная фильтрация всей базы остаётся задачей интеграции.
- Переключатели структуры принимают `data-filter` и `data-category`. В демонстрации есть только материалы институтов; остальные категории показывают пустое состояние, а не выдуманные данные подразделений.
- Программы подразделения фильтруются по уровню образования. Категорию можно передать через `data-category`; при отсутствии используется текст метки уровня.
- Хештеги новостей фильтруют имеющиеся карточки. В демонстрации исходные категории карточек одинаковы, поэтому одни фильтры возвращают все карточки, а отсутствующая категория — пустое состояние.
- Ссылки `program.html` в карточках программ ведут на общий демонстрационный шаблон; при интеграции заменить адресами конкретных программ.
- Пагинация имеет ссылки `?page=N`; реальную выборку страниц нужно связать с CMS. Локальная демонстрация не содержит 16 разных наборов данных.
- Целевые адреса новостей и нижних баннеров не предоставлены. Этот вопрос открыт и явно отмечен в `TESTING-CHECKLIST.md`; фиктивные адреса детальных материалов не подставлялись.

Внешние API требуют доступности сети и корректных настроек учётной записи. Проверка локальной сборки не подтверждает работоспособность ключа Яндекс.Карт на будущем домене.
