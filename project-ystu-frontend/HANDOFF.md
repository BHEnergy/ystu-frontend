## Где production-версия

Готовая статическая сборка: `project-ystu-frontend/dist/` (папка `dist` рядом с этим документом). Главная страница: `dist/pages/index.html`. Для размещения копировать содержимое `dist` целиком, сохраняя относительные пути. Это production-сборка фронтенда, а не готовая серверная интеграция с 1С-Битрикс.

Демонстрационный сайт: https://bhenergy.github.io/ystu-frontend/pages/index.html

GitHub Pages использует основные `pages/`, `css/`, `js/`, `images/` в корне репозитория; их пути к стилям отличаются от `dist/styles/`. Основные страницы синхронизированы с компонентной сборкой. Не смешивать ресурсы двух вариантов размещения.

## Что передавать разработчику

Папку `project-ystu-frontend` с `src`, `dist`, `scripts`, `package.json`, `package-lock.json`, README и документами интеграции. Не передавать `node_modules`, Git-историю и внутренние аудиты. Существующие ZIP-архивы автоматически не обновляются.

Исходники страниц: `src/pages/*.njk`. Общие компоненты, включая шапку и подвал: `src/templates/components/`. Стили: `src/styles/`. Скрипты: `src/js/`. Сгенерированный `dist` вручную не редактировать.

## Сборка и проверка

В каталоге `project-ystu-frontend`:

```sh
npm ci
npm run build
npm test
node scripts/check-client-fixes.cjs
npm run test:ui
npm run test:ui:legacy
```

Для браузерных проверок нужен установленный Chrome. `node scripts/media.cjs` обновляет WebP после изменения исходных изображений. `node scripts/sync-legacy.cjs` собирает `dist` и обновляет основные файлы в родительском репозитории; отсутствующие основные HTML-страницы не восстанавливает.

## Изменения этой передачи

- WebP с PNG/JPEG fallback; исправлена геометрия изображений на detail-structure и student-life.
- Поиск в шапке ограничен контейнером; мобильные иконки 44×44 px с gap 12 px. Закрытие мобильного меню закрывает поиск; десктопный поиск не перекрывает кнопку меню. Поиск работает и при задержанной загрузке компонента шапки.
- Восстановлены исходные буллеты слайдеров.
- Пагинация: синие ссылки, выделение выбранного номера, переключение номерами и стрелками; событие `pagination:change` содержит `detail.page`.
- Клиентская проверка формы, доступное прикрепление файла, демонстрационные фильтры, адаптивный CMS-контент `.wyswig`, исправления ссылок и обработки отсутствующих элементов.

## Границы реализации

На news-events пагинация переключает два демонстрационных набора по шесть записей на страницу; второй набор содержит две новости и два события. Выбранная вкладка и номер страницы связаны с URL (`tab`, `page`), работают повторное открытие и история браузера. В демонстрации UI Kit без связанного списка пагинация сохраняет визуальное переключение. Фильтрация использует демонстрационные `data-catalog-filters`, поиск — названия страниц комплекта. Проверка телефона проверяет полноту маски, не существование номера. Реальные данные, серверная валидация, отправка форм, поиск и фильтрация по базе подключаются на этапе интеграции. Демонстрационное сообщение об успехе не является подтверждением доставки формы.

`dist/pages/map-test.html` — диагностический стенд, не включать в публичную навигацию. Основной `pages/map-test.html` удалён. Настройки ключа карт и разрешённых доменов проверить для целевого размещения.
