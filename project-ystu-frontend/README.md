# ЯГТУ — компонентные frontend-шаблоны

Статическая вёрстка для интеграции в 1С-Битрикс. Шапка, подвал и общие компоненты хранятся в отдельных Nunjucks-шаблонах. Изменение одного шаблона после сборки применяется ко всем использующим его страницам, включая UI-kit. На выходе — обычные HTML, CSS и JavaScript, без клиентского фреймворка.

## Быстрый старт

Нужны Node.js 20+ и npm.

```sh
npm ci
npm run dev
```

Открыть `http://localhost:8000/pages/index.html`. Изменения в `src` автоматически пересобираются; страницу в браузере обновлять вручную. Порт можно изменить переменной окружения `PORT`.

Для готовой сборки:

```sh
npm test
npm start
```

`npm test` выполняет сборку и проверяет локальные ресурсы и общие компоненты. Только сборка: `npm run build`. Команда пересоздаёт `dist`; правки напрямую в `dist` будут потеряны. Исходный проект вне этой папки не затрагивается.

Браузерные регрессионные проверки: `npm run test:ui` (нужен установленный Google Chrome). Команда пересобирает `dist`, проверяет интерфейс на 390/1440 px, меню в невысоких окнах и сохраняет скриншоты в `test-results/`. Внешние API в этом тесте намеренно отключены. Итоговый перечень исправлений и границы проверки: [TESTING-CHECKLIST.md](TESTING-CHECKLIST.md).

## Структура

```text
src/
  templates/
    layouts/base.njk           # общий HTML-документ
    components/               # общие компоненты
  pages/                      # страницы .njk, включая UI-kit
  data/                       # параметры страниц и данные меню
  styles/
    base/                     # базовые стили, шрифты, переменные
    layout/                   # шапка, подвал, мега-меню
    components/               # переиспользуемые блоки
    pages/                    # специализированные стили страниц
    utilities/                # Bootstrap и сетка
    styles.css                # общая точка входа
  js/
    components/               # логика блоков и локальные библиотеки
    main.js                   # загрузка и инициализация
  images/
  fonts/
  index.html                  # переход на pages/index.html
dist/                         # готовые страницы и ресурсы
scripts/                      # сборка, проверки, локальный сервер
package.json
package-lock.json
README.md
INTEGRATION.md
THIRD-PARTY-NOTICES.md
```

## Где редактировать

| Задача | Файл |
| --- | --- |
| Шапка и мега-меню | `src/templates/components/header.njk` |
| Верхняя навигация и иконки | `src/templates/components/navbar.njk` |
| Пункты первого уровня меню | `src/data/navigation.json` |
| Подвал и контакты | `src/templates/components/footer.njk` |
| Содержимое страницы | `src/pages/<имя>.njk` |
| Каталог компонентов | `src/pages/ui-kit.njk` |
| Тексты и ссылки баннера курсов | `src/data/pages.json` |
| Общие стили | `src/styles/styles.css` и его импорты |
| Поведение компонентов | `src/js/components/`, `src/js/main.js` |

Пример подключения компонента:

```njk
{% include "components/footer.njk" %}
```

Пример параметризованной опции фильтра:

```njk
{% set option = {"label": "Очная", "name": "study_form[]", "value": "full_time", "type": "checkbox", "checked": true} %}
{% include "components/catalog-filter-option.njk" %}
```

Для новой страницы создать `.njk` в `src/pages`, унаследовать `layouts/base.njk` и заполнить блоки `head`, `bodyAttributes`, `content` по существующей странице. Сборщик автоматически создаст одноимённый `.html`. Относительные ссылки на страницы сохраняются в виде `programs.html`, на ресурсы — `../styles/…`, `../images/…`.

## Передача и публикация

### Проверка и обновление изображений

- `node scripts/media.cjs` — пересоздать WebP и манифест размеров после изменения растровых изображений в `src/images/fallback`. Используется Sharp (версия фиксируется в `package-lock.json`). Исходные PNG/JPEG сохраняются как fallback; сборщик добавляет `<picture>` и размеры в HTML.
- `node scripts/sync-legacy.cjs` — собрать `dist` и перенести изменения в основные `pages`, `css`, `js` и изображения родительского проекта. Отсутствующие основные HTML-файлы не восстанавливаются автоматически.
- `node scripts/check-client-fixes.cjs` — проверить формы, фильтры, CMS-контент, адаптивные изображения и поиск в основных страницах и `dist` (требуется установленный Chrome).

### Границы демонстрационной логики

Фильтры используют JSON в `data-catalog-filters` у карточек. Это демонстрационные метаданные, не подтверждённые сведения о программах и вакансиях. При интеграции заменить их данными CMS. Поиск демонстрирует поиск по названиям страниц комплекта, а не по базе сайта. Проверка телефона на клиенте проверяет полноту маски, но не существование номера. Серверная валидация, отправка форм и поиск/фильтрация по базе подключаются при интеграции; демонстрационная логика не заменяет их.

- Разработчику передавать эту папку с `src`, `dist`, скриптами, обоими package-файлами и инструкциями, без `node_modules`.
- Для статического размещения публиковать только содержимое `dist`. Общие компоненты уже вставлены в каждую HTML-страницу; дополнительный сервер шаблонов не нужен.
- `pages/map-test.html` сохранена как диагностический стенд. Не включать её в рабочую навигацию; при публикации рабочего сайта исключить.
- `docs`, `.vscode`, `.codex`, Git-история и внутренние аудиты не входят в передаваемую папку. Контрольные кадры `images/check-in` не включаются в сборку.
- Старый архив рядом с папкой не обновляется автоматически. Актуальны исходники и `dist` в этой папке.

Порядок подключения к CMS, параметры вариантов и ограничения описаны в [INTEGRATION.md](INTEGRATION.md). Перечень сторонних ресурсов — в [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md).
