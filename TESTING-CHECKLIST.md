# Чек-лист тестирования вёрстки ЯГТУ

Актуальный результат проверки локальной production-сборки: [отчёт от 07.10.2026](PRODUCTION-AUDIT-2026-10-07.md). Найдены дефекты; чек-лист полностью не закрыт. Подробности, выполненные и непроверенные сценарии разделены в отчёте.

Чек-лист — список действий, которые нужно выполнить перед передачей сайта. Для каждого действия указано, какой результат ожидается. Проверяем не только внешний вид, но и работу кнопок, меню, форм и адаптива.

Этот раздел составлен 07.10.2026. Его пункты пока НЕ проверены в рамках текущей задачи. Ниже отдельно сохранён предыдущий отчёт: его результаты нельзя автоматически переносить на новую сборку.

## 1. Как пользоваться

1. Зафиксировать версию сайта и открыть её через локальный веб-сервер или опубликованный адрес, не через двойной клик по HTML.
2. Пройти общие проверки на каждой странице. Затем выполнить специальные сценарии из раздела 6.
3. Отмечать результат: **ОК**, **Ошибка**, **Не проверено**, **Не применимо** (с причиной).
4. Для ошибки записать страницу, размер окна, действия и приложить скриншот.
5. После исправления повторить не только неудачный сценарий, но и проверить соседние состояния. Для общего компонента проверить остальные страницы, где он используется.

Галочка `[x]` ставится только после успешной проверки. Если один пункт проверен на компьютере, но не на телефоне, отдельно записать это в таблице результатов.

## 3. Общая проверка каждой страницы

- [ ] Страница открывается по прямому URL и после обновления; изображения, шрифты, CSS и JS загружаются.
- [ ] Нет горизонтальной прокрутки всей страницы. Исключение — специально прокручиваемые таблицы и слайдеры.
- [ ] Текст не обрезан и не налезает на соседние блоки; длинные заголовки и подписи помещаются.
- [ ] Хлебные крошки и первый экран не скрыты под фиксированной шапкой.
- [ ] Порядок секций, ширина контейнера, отступы, размеры текста, цвета и скругления сверены с актуальным макетом.
- [ ] Фотографии не растянуты; обрезка изображений соответствует макету.
- [ ] Кнопки и ссылки имеют ожидаемые состояния: наведение, нажатие, клавиатурный фокус, отключённое состояние.
- [ ] Ссылки ведут на согласованные страницы. Заглушки и отсутствующие адреса записаны отдельно.
- [ ] Отступ перед футером соответствует принятому решению: 110 px на десктопе, 80 px на мобильном; нет двойного отступа от последнего блока.
- [ ] При увеличении масштаба браузера до 200% основные действия остаются доступными.
- [ ] На медленной загрузке появление изображений и шрифтов не создаёт существенных скачков интерфейса.
- [ ] В консоли нет необработанных ошибок JS; в Network нет неожиданных 404 для локальных ресурсов.

Для точного сравнения сохранить скриншоты при одинаковой ширине окна, загрузить шрифты и изображения, дождаться окончания анимаций. Сравнивать также отдельные блоки: один длинный скриншот не позволяет надёжно оценить мелкие отступы.

## 4. Шапка и подвал — общий сценарий

Поведение полностью проверяется один раз для общего компонента. Его присутствие, выравнивание, ссылки и отсутствие конфликтов с содержимым проверяются на каждой странице.

### Шапка и десктопное меню

- [ ] Логотип, ссылки и кнопка «Меню» выровнены по вертикали; в пунктах нет лишних переносов строк.
- [ ] При прокрутке шапка фиксируется плавно, не прыгает и не закрывает важные элементы.
- [ ] Открыть и закрыть меню в начале и середине страницы: положение прокрутки не сбрасывается.
- [ ] Бургер превращается в крестик; слово «Меню» скрывается при открытии и полностью возвращается после закрытия.
- [ ] Навести на раздел с подменю: центральная колонка меняется; можно перевести указатель в неё и нажать ссылку.
- [ ] Нажатие на ссылку ведёт по её адресу; активная подсветка не остаётся на несоответствующем разделе.
- [ ] Разделительные линии, фон активного раздела и цвета трёх колонок соответствуют согласованному варианту.
- [ ] В окне 1440×600 меню прокручивается; последний пункт доступен и мышью, и клавиатурой.

### Мобильное меню

- [ ] При открытии белая поверхность перекрывает контент, элементы управления остаются в пределах экрана.
- [ ] Первый клик по закрытой секции раскрывает её содержимое.
- [ ] Повторный клик по названию/телу раскрытой секции выполняет переход по ссылке.
- [ ] Клик именно по стрелке раскрытой секции сворачивает её, не выполняя переход.
- [ ] Стрелки и подсветка соответствуют открытому состоянию.
- [ ] Длинное меню прокручивается, при этом фоновая страница не прокручивается.
- [ ] Закрытие возвращает пользователя к прежней позиции страницы.
- [ ] После изменения ориентации и перехода между мобильной и десктопной шириной не остаются зависшие панели и блокировка прокрутки.

### Подвал

- [ ] На всех страницах одна актуальная версия футера, включая логотип компании.
- [ ] Контактные ссылки работают: телефон — tel:, почта — mailto:.
- [ ] Колонки корректно перестраиваются; длинные адреса и названия не растягивают страницу.

## 5. Повторяющиеся интерактивные компоненты

### Слайдеры

- [ ] Нажать «Вперёд» и «Назад», затем повторить свайпом на телефоне: меняется нужный слайдер, соседние не затрагиваются.
- [ ] Число видимых карточек и строк соответствует варианту слайдера и ширине экрана.
- [ ] Буллеты, где предусмотрены, меняют слайд и показывают текущую позицию; стоят на одном уровне со стрелками.
- [ ] У незакольцованного слайдера крайняя стрелка отключается. У закольцованного переход через край работает без пустоты.
- [ ] Большие и маленькие стрелки одного слайдера синхронно получают disabled.
- [ ] При недостаточном числе карточек нет пустых пролистываний и лишнего доступного управления.
- [ ] Стрелки доступны через Tab и работают по Enter/Space.
- [ ] При изменении ширины слайдер пересчитывается без наложений и пустых карточек.

### Табы и аккордеоны

- [ ] Выбор вкладки меняет содержимое, а не только цвет; повторный выбор не ломает состояние.
- [ ] Пустая категория показывает понятное сообщение, которое исчезает после возврата к заполненной.
- [ ] Аккордеон раскрывается и закрывается плавно, текст не обрезается.
- [ ] Закрытый аккордеон не оставляет случайных отступов; его скрытые ссылки недоступны через Tab.
- [ ] Клавиши Enter/Space открывают аккордеон; aria-expanded соответствует состоянию.

### Формы и модальные окна

- [ ] Каждая кнопка открытия показывает нужную форму, а не другую модалку.
- [ ] Модалка помещается в невысокий экран или прокручивается; крестик всегда доступен.
- [ ] Закрытие крестиком и Escape работает; фокус возвращается к кнопке открытия.
- [ ] Tab не уходит за открытую модалку; фоновая страница не прокручивается.
- [ ] Пустые обязательные поля, неправильная почта, неполный телефон и отсутствие согласия показывают понятные ошибки.
- [ ] После исправления значения ошибка снимается; введённые данные не исчезают неожиданно.
- [ ] Телефонная маска корректна при вводе, вставке и удалении; проверены поля с data-validate="phone".
- [ ] Галочка согласия центрирована, состояние checked и анимация соответствуют оформлению.
- [ ] Окно успешного завершения можно проверить отдельной демонстрационной кнопкой; это не подтверждение доставки данных на сервер.
- [ ] После повторного открытия и закрытия нет дублирующихся обработчиков и зависшего затемнения.

### Анимации и доступность

- [ ] Наведения на новости, карточки и декоративные линии плавные и не меняют размеры соседних блоков.
- [ ] Счётчики статистики доходят до правильных значений и не показывают NaN; длительность соответствует ТЗ.
- [ ] При включённом «Уменьшении движения» необязательные анимации отключены или сокращены.
- [ ] Все управляющие элементы доступны с клавиатуры, фокус виден.
- [ ] Иконки-кнопки имеют доступные названия; информативные изображения — осмысленный alt, декоративные — пустой alt.
- [ ] Размеры зон нажатия проверены на телефоне; у пагинации целевой размер не меньше 44×44 px.

- [ ] Выполнен npm run test:ui для компонентной сборки и npm run test:ui:legacy для основной версии. Сохранены результаты обоих прогонов.

## 8. Что проверяем сейчас, а что после интеграции

| На этапе вёрстки | После подключения 1С-Битрикс / сервера |
| --- | --- |
| Адаптив, состояния, анимации, доступность, локальные ресурсы | Динамический вывод реальных данных и права доступа |
| Раскрытие фильтров и работа согласованной демонстрационной фильтрации | Поиск и фильтрация по всей базе, серверная пагинация |
| Поля, маска, клиентские ошибки, отображение модалки результата | Реальная отправка, серверная валидация, доставка уведомлений, защита от спама |
| Корректные HTML, alt, доступные названия и структура заголовков | HTTP-статусы, редиректы, серверное кеширование и сжатие |
| Подключение API и интерфейс карты, если входят в согласованный объём | Рабочие ограничения ключа, реальные координаты и данные объектов |

Перенос серверной задачи на интеграцию не оправдывает неработающую кнопку, сломанный адаптив или некорректную HTML-разметку. Границы ответственности и недостающие данные фиксируются явно.

- Версия / коммит:
- Браузер и устройство:
- Размер области страницы:
- Действия для повторения:
- Ожидаемый результат:
- Фактический результат:
- Скриншот / видео:

- Результат повторной проверки и дата:

## Ограничения и открытые вопросы

В проверенных локальных сценариях критических сбоев не обнаружено. Это не означает, что все замечания отчёта закрыты: пункт 13 требует целевых URL и остаётся открытым для новостей/баннеров.

Тестирование выполнено в установленном Google Chrome на Windows. Safari/iOS, Firefox, реальные мобильные устройства, сторонние сервисы и серверная интеграция этим прогоном не проверялись. Внешние API в автоматическом UI-тесте намеренно отключены. W3C и Lighthouse повторно не запускались; результаты предыдущих проверок не приписываются новой версии.

Поиск и фильтры работают с уже выведенными демонстрационными карточками. Все новости из исходного примера имеют одинаковые категории: фильтр может вернуть полный набор либо пустое состояние. Данные остальных разделов структуры не выдумывались. Реальная пагинация по базе, поиск по всему сайту, доставка форм и замена демонстрационных ссылок остаются задачами интеграции.

Перед передачей исправленной версии заказчику необходимо согласовать адреса новостей и нижних баннеров, закрыть пункт 13, затем повторить проверки.
